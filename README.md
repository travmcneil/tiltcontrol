# Tilt Control

An Android app that turns your phone into a visual (and audible) pinball tilt-bob simulator. Pick a location, pick a machine, and get a live, physics-based representation of that machine's tilt bob — calibrated to how *that specific machine* sits and behaves, complete with proximity warnings and a full tilt alarm.

## What it does

Real pinball machines use a hanging "tilt bob" — a weight that swings inside a ring, and completes a circuit (triggering a tilt warning) if the machine is nudged too hard. Tilt Control simulates that using your phone's accelerometer:

- Organize machines by **location** (e.g. the arcade or venue you're playing at)
- Each machine gets its own **calibration** — since every machine sits at a slightly different angle/orientation, a raw accelerometer reading isn't meaningful on its own
- A live on-screen dot swings around a ring, simulated with real pendulum physics (mass, spring stiffness, and damping) rather than snapping directly to the raw sensor reading — it lags and settles the way a real weighted bob would
- A backup-sensor-style audio cue rises in volume as the bob approaches the ring
- A distinct alarm siren plus a vibration pulse fires once the bob actually crosses the threshold
- Per-machine tilt sensitivity can be fine-tuned on the fly with +/- buttons, without needing to fully recalibrate

## Tech stack

- **Kotlin** — primary language
- **Jetpack Compose** — UI toolkit (declarative, similar in spirit to React)
- **Room** — local SQLite database for storing locations, machines, and calibration data
- **Navigation Compose** — screen-to-screen navigation
- **Android Sensor API** (`SensorManager` / `TYPE_ACCELEROMETER`) — live tilt data
- **AudioTrack** — synthesized proximity tone and alarm siren (no audio asset files needed)
- **Vibrator / VibratorManager** — haptic feedback on tilt

## How calibration works

1. Prop the phone against the machine in the position you'll leave it during play
2. Tap **Calibrate** — this reads the current accelerometer values and saves them as that machine's baseline, and resets the pendulum simulation so no leftover momentum carries over
3. During play, the tilt bob's on-screen position reflects `current reading − baseline`, smoothed through the pendulum simulation, so the dot starts centered regardless of the machine's resting angle
4. Movement past the threshold distance from center turns the dot red and triggers the full tilt alarm

## Tilt sensitivity (threshold) adjustment

Each machine stores its own `tiltThreshold` value. On the tilt screen, **−** and **+** buttons nudge it in small increments (±0.1) and save the change immediately, without needing to recalibrate. The current value is shown on screen. This is useful for machines that are naturally looser or tighter than your default calibration.

## Audio & haptic feedback

- **Proximity tone** — a continuous tone whose volume rises the closer the bob gets to the outer ring (quiet through most of the distance, ramping up sharply near the edge, similar to a car backup sensor)
- **Alarm siren** — an alternating-pitch tone that takes over once the bob fully reaches the ring, paired with a short vibration pulse
- Both are synthesized in-app (no sound files), and are automatically silenced if the app is backgrounded or the screen is left, so nothing keeps playing after you've stopped looking at it

## Building & running

1. Open the project in Android Studio
2. Let Gradle sync complete (Room, Navigation, and Material Icons Extended dependencies are already configured in `build.gradle.kts`)
3. Connect a physical Android device via USB with **USB Debugging** enabled (accelerometer testing requires a real device — emulators fake sensor data manually)
4. Select your device from the device dropdown in the toolbar and click **Run ▶**

### Required permission

Vibration requires a manifest entry — confirm this is present in `AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.VIBRATE" />
```

### Installing a built APK manually

```
adb install app/build/outputs/apk/debug/app-debug.apk
```

If `adb` isn't recognized, either use its full path under `<SDK location>/platform-tools/adb.exe`, or add that folder to your system PATH.
